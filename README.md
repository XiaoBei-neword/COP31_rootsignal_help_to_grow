# 根脉 RootSignal

给小农户的气候决策工具。把「未来几天的气候异常」翻译成三件能立刻执行的事：
**灌不灌、什么时候收、收上来怎么调度**——最后落到一个数：**少损失多少斤、多少钱**。

> 比赛赛道：可持续食物与农业 · 本地运行版 Flask 应用，不部署公网。

---

## 1. 跑起来（3 分钟）

**双击 `start.bat` 就行。** 脚本会自己找 Python、缺依赖时自动安装、补齐演示账号，然后打开 <http://127.0.0.1:5000>，用 `demo_a / demo1234` 登录。

> **那个黑色命令行窗口要一直开着。** 窗口关掉服务就停了，浏览器再刷新就会显示「127.0.0.1 拒绝连接」。
> 重复双击也不会出错：脚本发现端口上已经有根脉在跑，会直接帮你打开浏览器。

命令行方式等价于：

```bash
# 1) 依赖（已装 Flask / requests / python-dotenv 可跳过）
python -m pip install -r requirements.txt

# 2) 生成两个演示账号（已存在会跳过，不重复写记录）
python seed_demo.py

# 3) 启动
python app.py
```

> 需要 Python 3.9+（实测 3.13 通过）。
> `start.bat` 的查找顺序：项目内 `.venv` → `py` 启动器 → 常见安装目录 → `PATH` 里的 `python`；全都没有会提示去装，不会一闪而过。
> 本机即使没装 `py` 启动器也能跑，脚本会自动回退到 `python`；缺依赖时会自动 `pip install`，默认源失败会换清华镜像。
> 想跳过自动开浏览器，启动前设 `set NO_BROWSER=1`。

## 2. 配置密钥（不配也能跑，但会标注为演示数据）

复制 `.env.example` 为 `.env`，按需填写。

**气象**（三选一，`WEATHER_PROVIDER=auto` 时按顺序自动挑选）

| 数据源 | 配置项 | 是否需要 Key | 说明 |
| --- | --- | --- | --- |
| Open-Meteo | 无需配置 | 否 | 默认走这条，真实预报，含 FAO 参考蒸散 ET0，16 天窗口 |
| 和风天气 | `QWEATHER_KEY` | 是 | 国内最常用，免费开发版够用；新版账号的 Host 形如 `https://xxx.re.qweatherapi.com`，填到 `QWEATHER_HOST` |
| 心知天气 | `SENIVERSE_KEY` | 是 | 备选 |

三者都失败时，若 `ALLOW_DEMO_WEATHER=true`，会回落到**演示数据**——
页面顶部、侧栏、数据角标会同时出现「演示数据（模拟）」，绝不伪装成真实气象。

**大模型**（任意 OpenAI 兼容接口）

```ini
LLM_PROVIDER=deepseek        # deepseek / dashscope / moonshot / zhipu / openai
LLM_API_KEY=sk-xxx
# 也可以不用预设，直接指定：
# LLM_BASE_URL=https://api.deepseek.com/v1
# LLM_MODEL=deepseek-chat
```

没配 Key 时，灌溉模块自动降级为**本地规则引擎**，界面上明确标注「本地规则引擎」而不是「大模型」。
Key 只从环境变量 / `.env` 读取，源码里没有任何硬编码。

## 3. 三个模块在做什么

### 01 田间风险看板
- 取地块坐标的实时天气 + 逐日预报（最高/最低温、降水、湿度、风速）。
- 按作物参数逐项判风险：高温热害、低温冷害/霜冻、水分亏缺、暴雨内涝、大风倒伏、高湿病害。
- 综合指数 = 最高风险项 × 0.85 + 其余项之和 × 0.18，映射为 低/中/高/极高。
- 水分平衡：`ETc = ET0 × 生育期系数`，`Pe` 为有效降水，缺口即灌溉任务量。
- ET0 用 **Hargreaves-Samani**（缺测站要素时的 FAO 推荐替代法），由日最高/最低温 + 纬度天文辐射推算，不依赖额外传感器。

### 02 灌溉决策 Agent
- 把「3 日 ETc、有效降水、土壤有效水容量、灌溉水利用系数、风险明细」打包给大模型，要求输出结构化 JSON：决策 / 净灌水量 / 毛灌水量 / 每亩立方米 / 时段 / 理由 / 风险 / 复查时间。
- 提示词里明确约束：只能用给定数值，不得编造；灌水量与给定净需水一致，允许 ±15% 专业微调并说明理由。
- 前端有加载态（分步进度）、失败态（人话报错 + 「改用本地规则引擎」一键降级）。
- **支持多轮追问**：建议生成后可在同一页面继续对话（"为什么不现在灌""雨没下怎么办""换成砂土呢"）。每轮都会重新带上本次决策的同一批数据（作物/生育期/3 日水分平衡/风险明细），所以模型不会前后矛盾；对话历史保留最近 8 轮，换条件提问会按新条件重算而不是复述旧结论。
- 每次生成写入本账号记录，页面下方只显示自己的历史。

### 03 收获窗口与余量调度
- 按播种日期 + 全生育期推算成熟日，在预报里给每一天打分（降水、高湿、高温、大风、过熟/未熟），取最低分日为**最佳单日**，连续低分区间为**窗口**。
- 再看收获后 5 天降水，选择损失率情景；对比「常规方式」与「本方案」，给出可避免损失 kg 与折价。
- 余量调度拆成三步可执行动作：抢收排程、干燥与暂存、余量外运/订单对接，每步带数量与减损贡献。
- 页面提供「计算口径」折叠区，所有数字可复核。

闭环：**气候异常（看板）→ 灌溉动作（Agent）→ 收获窗口（调度）→ 少损失多少（测算）**。

## 4. 数据与隔离

SQLite，`data/rootsignal.db`。

| 表 | 说明 |
| --- | --- |
| `users` | 账号（用户名 + 密码哈希） |
| `farm_profiles` | 每账号一条地块档案：作物、坐标、面积、播种日期、土壤、灌溉方式 |
| `irrigation_records` | 灌溉决策记录，带 `user_id` |
| `harvest_plans` | 收获调度方案，带 `user_id` |

所有读写都带 `WHERE user_id = ?`，A 账号在 SQL 层就查不到 B 账号的数据。
现场验证：登录 `demo_a` 记录里有内容 → 退出 → 登录 `demo_b` → 记录区显示「还没有记录」。

## 5. 目录

```
根脉/
├─ app.py                 路由与页面组装
├─ config.py              环境变量 / 数据源状态 / 大模型预设
├─ db.py                  SQLite schema 与查询封装
├─ seed_demo.py           两个演示账号 + 预置记录
├─ data/
│  ├─ crops.json          8 种作物的阈值、需水、产量、损失率参数表
│  └─ rootsignal.db       运行后生成
├─ services/
│  ├─ weather.py          和风 / 心知 / Open-Meteo / 演示数据 四种 provider + 地点检索
│  ├─ agronomy.py         ET0、风险打分、灌溉规则、收获窗口、余量调度
│  └─ llm.py              OpenAI 兼容调用、JSON 解析与校验、错误翻译
├─ templates/             base / login / register / dashboard / irrigation / harvest / settings / error
├─ static/css/app.css     Biomimetic / Organic 2.0 视觉系统
├─ static/js/             charts.js（手写 SVG 图表）/ agent.js / harvest.js / settings.js / app.js
├─ docs/DEMO.md           现场演示脚本
└─ .env.example
```

前端不依赖任何 CDN：图表是手写的 SVG，断网也能渲染。

## 7. 边界

- 不做线上部署、域名、HTTPS；不做找回密码、第三方登录、角色权限。
- 不接传感器/物联网，不自研气象模型，不做本地模型训练。
- 不做交易、支付、物流等延伸功能；不专门适配移动端（桌面演示为主）。
- 产量、价格、损失率为参数表中的参考值（`data/crops.json`），实际使用应按当地农技站口径校准。
